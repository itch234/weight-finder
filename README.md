# ウェイトファインダー

画面の中の「重さ」がどちらに偏っているかを測って、カメラを向け直す方向を出すWebアプリです。
ビルドも依存パッケージも不要で、`index.html` をブラウザで開くだけで動きます。

**公開URL:** https://itch234.github.io/weight-finder/

## できること
- **カメラを起動** — ライブ映像をリアルタイム判定(カメラの利用には https 配信が必要)
- **撮影** — 構図が整ったらその場で保存。切り抜き枠(比率)の中身をカメラの解像度のままJPEGにします。スマホでは共有シート(写真に保存など)、パソコンではダウンロード。一時停止中の画面も撮影できます
- **カメラ切替** — 前面 ⇄ 背面を切り替え。前面カメラは鏡像で表示し、判定・矢印・保存もその向きに揃えます
- **写真で判定** — 手元の画像ファイルを読み込んで判定。パソコンでは画像のドラッグ＆ドロップや貼り付け(Ctrl+V)でも読み込めます
- **複数写真の比較** — 写真をまとめて選ぶと、画面下に一覧が並び、いまの判定モード・比率での点数を各写真に表示します。いちばん高い写真に黄色の印。タップ(または ← → キー)で切り替え
- **この枠で保存** — 写真で判定中は、選んだ比率で切り抜いたJPEGを保存できます
- **デモで試す** — 写真やカメラの許可なしで、サンプル画像の判定を体験
- **終了する** — カメラの使用を停止し、最初の画面に戻る
- **重心モード** — 画面全体の重さの中心が中央付近に来るよう、カメラを振る方向を矢印で表示
- **三分割モード** — 主役を三分割構図の交点に乗せる方向を表示
- **写真の主役を指定** — 三分割モードで写真をタップすると、顔・目・物など狙いたい位置を指定できます。Tabで写真に移動して矢印キー（Shiftで大きく移動）でも操作できます。Escapeまたは「主役を自動に戻す」で解除。比較中は写真ごとに指定を保持し、枠外になった主役は採点しません。ライブ映像の追跡機能ではありません
- **重さマップ** — 重いと判定された領域を可視化
- **比率** — フル / 3:2 / 4:3 / 5:4 / 1:1 / 16:9 のトリミング枠を切り替え
- **ZV-E10のレンズ画角** — 「画角: 通常」からSIGMA 16mm、SONY ZEISS 24mm、TTArtisan 50mm、VILTROX 85mmを選択。スマホのカメラ映像に相当範囲の枠を表示し、枠内だけを解析・保存します。写真読み込みには適用しません
- **振動の合図** — ライブ判定で構図が整った瞬間に短く振動します(対応端末のみ)。画面を見ずに構えているときの目印
- **設定の記憶** — 判定モード・比率・カメラの向きは、次に開いたときも引き継がれます
- **ホーム画面に追加** — スマホのブラウザから「ホーム画面に追加」すると、全画面のアプリとして起動でき、オフラインでも開けます

写真では重さの偏りと主役の位置を表示し、ライブ映像ではカメラを向け直す方向を表示します。
点数は目標の構図への近さの目安で、写真の良し悪しを評価するものではありません。
透明な画像は、表示・判定・JPEG保存を白背景に統一します。
写真・映像はブラウザ内で処理され、サーバーへ送信されません(表示フォントはGoogle Fontsから読み込みます)。

重心・三分割の選択は、Tabで移動した後に矢印キーまたはHome / Endでも切り替えられます。
パソコンでは、ボタン以外にフォーカスがある状態でスペースキーを押すと撮影・保存できます。
カメラの起動中でも写真・デモを選択でき、最後に選んだ入力が優先されます。
読み込めない画像やカメラの起動失敗時には、表示中の写真を残してエラーを案内します。

## 重さの推定方法

### ZV-E10・iPhone 14での画角設定

ZV-E10の静止画（センサー23.5×15.6mm）を基準にしています。16/24/50/85mmは通例の1.5倍換算で約24/36/75/127.5mm相当です。F値は画角計算に使いません。VILTROXのモデル末尾によらず85mmとして扱います。

1. カメラを起動し、「画角: 通常」でレンズを選びます。
2. iPhone 14の1×では67.3°、0.5×では106.2°を仮値として用意しています。これはApple公表の26/13mm相当から、4:3の理想的な投影を仮定して求めた長辺画角であり、Safari映像の実測値ではありません。0.5×の数値ボタンだけでカメラは切り替わりません。カメラ欄に超広角が表示される場合はそれを選択してください。
3. 同じ位置・向きで遠方の景色をZV-E10と比較し、枠が同じ範囲を囲むよう「長辺画角」を調整してください。数値を大きくすると枠は小さくなります。横持ちでは左右、縦持ちでは上下の角度です。スマホのカメラ、ズーム、映像の縦横や記録条件が変わったら再確認してください。

計算はピンホールモデルです。スマホ映像の長辺の画素数をL、設定した長辺画角をθとすると、画素単位の焦点距離は `L / (2 tan(θ/2))`。これにZV-E10のセンサー幅または高さを掛け、選んだレンズの実焦点距離で割ると枠の寸法になります。「比率」はその枠をさらに切り抜きます。枠がスマホ映像に収まらない場合は採点・保存を停止し、足りない範囲を黙って省略しません。

16mmの画角はiPhone 14の標準1×より広く、超広角が必要になる場合があります。ブラウザが超広角を公開しない場合、その端末では枠全体を再現できません。85mmではスマホ映像の小さな部分を使うため、細部の精度・保存画素数が低下します。遠近感を合わせるには同じ位置から見る必要があり、ボケ・被写界深度・歪曲・フォーカスブリージングは再現しません。動画の追加クロップにも未対応です。

仕様の参照: [Sony ZV-E10](https://www.sony.jp/ichigan/products/ZV-E10/spec.html)、[Apple iPhone 14](https://support.apple.com/ja-jp/111850)。実機の画角一致精度は未検証です。

### 解析モデル
各ピクセルをCIE Lab色空間に変換したうえで、以下を合成して「重さ」としています。

**目立ちの土台**

- 大域の目立ち(画面平均色との差)
- 局所の目立ち(周囲との差)
- 細部の密度(輝度のSobel勾配)。ピントの合った領域ほど高くなるので、ボケの判定も兼ねます

**重さの補正**

- 鮮やかなほど重い。色相は赤でもっとも重く、黄に向かうほど軽い
- 画面平均より暗いものほど重い(最大1.35倍)
- 肌色らしい領域は重い(最大1.9倍)。人物が注意を引くことを参考にした色の補正であり、顔や人物を検出しているわけではありません
- まわりが空いている要素は重い(最大1.5倍)。近傍の重さと、広い範囲の重さの差で測ります
- 画面の上にあるものほど重い(±10%)

解析は長辺160pxに縮小したフレームに対して行い、ライブ時は指数移動平均で結果を平滑化しています。
複数写真の比較では、各写真を長辺320pxに縮小して保持し、モードや比率を変えるたびに採点し直します(最大60枚)。

### 根拠と限界
各要因の出典、学術研究との突き合わせ、採用しなかった要因の理由は [docs/visual-weight-research.md](docs/visual-weight-research.md) にまとめています。押さえておきたい点は次の4つです。

- 「重心を画面中心へ」は知覚バランスの研究を参考にした補助です。色・明暗などを合成するこのアプリの重さは、論文のDCM（暗さから計算する重心）とは異なります。係数・許容差・0〜100点の換算は独自設定で、実写真の人間評価との一致率は未検証です
- 肌色補正では木肌・砂・夕景も重く見積もることがあります（肌色らしさの画面平均が0.35を超えると徐々に弱め、0.55以上で無効化）。顔検出器は使っていません。三分割で自動の主役が違う場合は写真をタップして指定してください
- 三分割法そのものは、美的評価との相関が弱いという実験報告があります。三分割モードは「その構図に寄せたいときの補助」で、正解ではありません
- 左右の非対称(右が重い)は、研究間で結論が割れているため入れていません

## ファイル構成
- `index.html` — アプリ本体(解析コアとUIをすべて含む)。これ1つだけでも動きます
- `manifest.webmanifest` / `sw.js` / `icons/` — ホーム画面への追加とオフライン起動のためのファイル。`sw.js` はページ本体をネットワーク優先で取得するので、更新はそのまま反映されます
- `tests/` — 解析コアの回帰テストとブラウザ操作テスト
- `docs/visual-weight-research.md` — 重さの推定に使っている理論の出典と、実装との対応表

## ローカルで動かす
カメラを使うには `https` か `localhost` である必要があります。

```sh
python3 -m http.server 8000
# → http://localhost:8000/ を開く
```

## GitHub Pages の設定
Settings → Pages → Source に `Deploy from a branch`、Branch に `main` / `(root)` を選んで Save。
`.nojekyll` はJekyll処理をスキップするために置いています。

## テスト

Node.js 22以降で、依存パッケージを追加せずに解析の回帰テストを実行できます。

```sh
npm test
```

解析コアのテストには、ビジュアルウェイトの各要因が実際に効いているかの検証が含まれます。明度と彩度をそろえた合成画像で一要因だけを変え、重心が理論どおりの側へ寄ることを確認します(暗いほうが重い、肌色が重い、赤が黄より重い、上が重い、孤立が重い、肌色一色の背景では補正が無効になる)。

ブラウザの操作テストは、Playwright(`playwright` または `playwright-core`)が利用可能な開発環境で `npm run test:browser` を実行します。
既存のChromium系ブラウザ(Edge / Chrome)を使う場合は、環境変数 `BROWSER_PATH` に実行ファイルの絶対パスを指定してください。
デモ、画像の読み込み、キーボード操作、画面サイズ、撮影・保存、設定の記憶、複数写真の比較、ドラッグ＆ドロップ、カメラの拒否・タイムアウト・入力切替・前後切替・停止を検証します。
カメラはテスト用の映像で代用しているため、実機のカメラやOSの許可ダイアログ、共有シートは別途確認が必要です。
スクリーンショットは `test-results/` に出力します。

タップ指定・解除のみのテストは `npm run test:touch` です。`BROWSER_ENGINE=webkit` を設定するとPlaywrightのWebKitで実行できます（事前に `playwright install webkit` が必要です。`BROWSER_PATH` は解除してください）。通常のブラウザテストにもタッチ検証を含みます。iPhone相当の画面サイズとタッチ入力、clickを生成しない入力、解除、スワイプ・中断時の誤指定防止を確認します。これはiPhone実機のSafariでの確認とは別です。
